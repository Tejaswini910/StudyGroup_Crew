# Study Group Crew Reflection

The project now supports a learner-chosen subject and topic instead of only the original study-strategy examples. The strongest part is the context flow: the Topic Researcher combines Wikipedia extracts with any pasted syllabus sections, the Study Explainer turns that evidence into notes, and the Quiz Maker uses the notes and source IDs to form questions. The Fact-Checker then checks references, answer keys, options, and explanations before the study pack is saved. Streamlit adds a scored quiz, answer feedback, persistent session history, and report downloads. Testing confirmed that an arbitrary Computer Science topic can produce sources and a quiz, that a submitted score is recorded, and that the report is updated.

One failure during development was a mismatch between the new agent name, "Study Explainer," and the old dashboard label; the initial page test caught it and the role mapping was corrected. Another important limitation is that no AI model was configured in the repository. Ollama is optional and uses no API key, but without a running local model the app uses a clearly identified extractive fallback. That fallback summarizes retrieved extracts and turns source sentences into practice questions; it is not equivalent to newly generated teaching material. Wikipedia access also depends on internet connectivity, and the fact-checker checks citations and quiz structure, not the independent truth of every claim.

Next I would test with course-specific syllabi from several subjects, add stronger distractors and adaptive feedback, and evaluate generated notes with instructor review. I would also add source-quality controls beyond Wikipedia and support explicit learning objectives so quizzes can measure course outcomes rather than only recall. These changes would improve academic reliability while keeping clear which content came from sources, a local model, or fallback logic.
